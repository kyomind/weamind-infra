## Part 1：weamind-infra

### #9 kubectl 排查指令特訓

- 重要性：`★★★★★`
- 執行時機：**W6 獨立一週**
- 理由：後面所有主題的共同底座——Phase 2 可觀測性、Phase 3 CKA、面試 live troubleshooting，全部吃得到這一週的效益。

### #10 建立 `Darkmind/` 練習 YAML 包

- 重要性：`★★★★★`
- 執行時機：**W6 Day 1 建立，整週使用**
- 理由：沒有可重複 apply / delete 的固定 lab，command drill 會流於零碎。這是指令特訓能穩定運作的前提。

### #2 刻意製造壞 Pod 排查練習

- 重要性：`★★★★★`
- 執行時機：**W6 全週，尤其 Day 4 整合演練**
- 理由：最直接的 debug 故事來源。面試問「你遇過什麼問題」，這裡的每個場景都是可講的素材。

### #1 `kubectl port-forward` 實作

- 重要性：`★★★★☆`
- 執行時機：**W6 Day 3 自然涵蓋，不需獨立排**
- 理由：會出現在 Darkmind 排查流程中，也服務 Phase 2 的 Grafana 本機瀏覽。不用另外花時間，做到就會了。

### #15 面試素材：K8s 偏向 Stateless，DB 留 VM 的決策論述

- 重要性：`★★★★☆`
- 執行時機：**W6 每天結束前 15 分鐘口語練習**
- 理由：投入 15 分鐘整理成口語版就夠。你已經有完整的決策脈絡，只差練習「講出來」。不需要寫文件。

### #21 面試素材：ConfigMap / Secret CRUD 與更新行為差異

- 重要性：`★★★★☆`
- 執行時機：**W6 每天結束前 15 分鐘口語練習**
- 理由：WeaMind 已有實際經驗，只差把更新行為與 trade-off 講清楚。口語自問自答即可，投入低、收益高。

### #16 Phase 2 預學習：Metrics Server vs Prometheus 分工

- 重要性：`★★★★☆`
- 執行時機：**W7 第一天（Phase 2 開始前）做最小概念整理**
- 理由：不先釐清這個，Phase 2 很容易把 `kubectl top`、HPA、Prometheus、Grafana 全混在一起。但不需要提前做，Phase 2 開場做最自然。

### #17 面試素材：DaemonSet vs ReplicaSet 選型

- 重要性：`★★★☆☆`（從 ★★★★☆ 降級）
- 執行時機：**W6 口語練習時順帶涵蓋，不獨立排**
- 理由：這題要能講清楚「每節點型工作負載」和「承接服務流量的副本型工作負載」的差異，但不需要在 WeaMind 這個 repo 裡把 Traefik 的實際部署型態講得太死。對這個專案而言，`line-bot` 屬於 Deployment / ReplicaSet 型工作負載是明確的；DaemonSet 的更標準例子可放在 Phase 2 的 Node Exporter 觀察點補齊。

### #18 Phase 2 觀察點：Node Exporter DaemonSet manifest

- 重要性：`★★★☆☆`
- 執行時機：**W7 部署 Prometheus 時順手觀察**
- 理由：第二個 DaemonSet 實例，但價值建立在你已經進入 Prometheus 之後。不是前置主線，是部署過程的學習副產品。

### #19 Phase 2 觀察點：Prometheus 設定檔的 ConfigMap 檔案掛載

- 重要性：`★★★☆☆`
- 執行時機：**W7-W8 部署過程中順手觀察**
- 理由：和 WeaMind 的 env 注入形成對照，能回答「環境變數 vs volume 掛載」的面試題。但它是部署中的學習副產品，不需要獨立排。

### #20 面試素材：Secret 常見 type 與 WeaMind 對照

- 重要性：`★★★☆☆`
- 執行時機：**有空時 15 分鐘整理，或 CKA 準備期順手複習**
- 理由：難度低、可後補。三種常見 type 記住就好，不需要搶佔主線時數。

### #6 Init Container 實作：line-bot 啟動前檢查 PostgreSQL 連線

- 重要性：`★★☆☆☆`（從 ★★★☆☆ 降級）
- 執行時機：**Phase 2 或 CKA 準備期，有空再補**
- 理由：有真實場景，但不是當前最痛的缺口。面試時用口語描述「我會怎麼做」就夠，不一定要真的實作。

### #11 Kustomize 實作：用 overlay 管理 replica 數量差異

- 重要性：`★★☆☆☆`
- 執行時機：**不排入主線，視餘裕決定**
- 理由：概念上值得懂，但 WeaMind 沒有多環境壓力，現在更多是 bonus。

### #12 Uptime Kuma 部署：fanout routing + PV/PVC 實作

- 執行時機：**不排入主線**
- 理由：一石多鳥但範圍容易膨脹，會把你帶往多個支線。不適合當前時間壓力。

### #13 wea-data 改為 K8s CronJob

- 重要性：`★★☆☆☆`
- 執行時機：**不排入主線**
