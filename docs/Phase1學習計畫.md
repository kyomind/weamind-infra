# Phase1 學習計畫

> WeaMind 深化期的六週版摘要。保留高層架構，不展開每日 lesson。
> 目標是把「AI 輔助完成」轉成「真的懂、能講、能做」，並把排查能力練到可驗收。

### 版本定位

- 這份文件是 Phase 1 的中層摘要，介於總計畫和每日 lesson 之間。
- 它保留每週主軸、主要產出與節奏，不寫到 command-level 的細節。
- 若要看完整每日安排，回到六週版詳細計畫；若要看整體路線，回到 12 週計畫。

## 執行節奏

- 週一到週三：主學習日
- 週四：彈性日
- 週五：寫作、收斂、驗收
- 每日主線：約 3 小時
- 週上限：15 小時
- 英文：每日 45 分鐘，獨立於主線之外
- 當週狀態若偏累，優先保住主線與驗收，不硬補額外內容。
- 週六日保留為緩衝，不把它們算進主線輸出。

---

## Phase1 重點

- W1：建立流量路徑與架構講法
- W2：Deployment、ReplicaSet、Pod 與 K3s 基礎
- W3：Debug 骨架與工具
- W4：ConfigMap / Secret、LB、CI / Image Pipeline
- W5：TLS、cert-manager、總演練與收尾
- W6：kubectl 指令特訓與 Darkmind 壓力演練（Darkmind 是刻意做出壞 Pod 情境的練習沙盒）

### 每週驗收方向

- W1：能不能把 WeaMind 的流量路徑從外到內講完整。
- W2：能不能把 Deployment、ReplicaSet、Pod 的關係講清楚，並指出 K3s 選型理由。
- W3：能不能在看到異常狀態時，先從哪裡查、用哪個工具查，有基本直覺。
- W4：能不能分清 ConfigMap / Secret、LB / Health Check、CI / Image Pipeline 的責任邊界。
- W5：能不能說出 TLS 終止位置與 cert-manager 流程，並完成收尾整理。
- W6：能不能在壓力下用 `kubectl` 完成完整排查，而不是只會背指令。

### 常見風險

- 風險一：把「看懂」誤當成「會做」，所以每週都要留實際操作或排查驗收。
- 風險二：把第六週當成新增知識週，其實它是把前面學過的東西練成肌肉記憶。
- 風險三：想把每週都做滿，結果把節奏拉太緊，反而影響收尾與輸出。

### 產出原則

- 每週至少保留一個可以被對外說明的結果。
- 文章不是每週唯一重點，但每週都要留下可整理的素材。
- 先顧主題理解，再顧表達品質，不反過來。

## 一句話總結

用六週把 WeaMind 的實作經驗整理成可講、可答、可在壓力下重現的能力，同時保留穩定節奏與可持續輸出。
