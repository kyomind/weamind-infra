## 今天一定要學會的 5 件事

1. `printenv`、DNS 測試、TCP 測試、真正 client 連線，分別站在不同驗證層級，不能互相替代。
2. `404`、`500`、`timeout`、完全沒有 request log，第一輪更值得懷疑的層次通常不同。
3. `設定值正確`、`網路可達`、`認證成功`、`應用查詢成功` 是四種不同結論，不要混成一句「連線正常」。
4. app `logs` 和 container 內部驗證不是互斥關係，而是常常一個先回答「發生了什麼」，另一個再補「目前內部條件是否合理」。
5. 真正成熟的 debug 不是多跑幾個指令，而是清楚知道每個證據的邊界。

## 建議教學順序

1. 先切開幾種常見驗證：環境變數、DNS、TCP、client 連線、app `logs` 各自能回答什麼。
2. 再整理一條從 `Pod` 內部往外部依賴收斂的最小驗證梯子。
3. 接著用 `404`、`500`、`timeout`、沒有 request log 這四類症狀，示範第一輪判讀差異。
4. 然後收斂成一個通用原則：遇到問題時，先問自己「我現在缺的是哪一層證據」。
5. 最後幫我整理成短版報告與 3 到 5 個真正值得帶回 VS Code 的補強觀念。

如果我卡住，請先用 Web app / API / DB 這類白話例子，不要一開始就用太重的 Kubernetes 術語。
