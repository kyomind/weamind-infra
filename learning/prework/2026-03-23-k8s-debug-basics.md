## 今天一定要學會的 5 件事

1. Pending、CrashLoopBackOff、ImagePullBackOff、CreateContainerError 這些狀態，不只是錯誤名稱，而是排查時的第一個訊號。
2. 同樣是 Pod 起不來，不同狀態代表你應該優先懷疑的方向不同，例如排程、映像、啟動或設定問題。
3. 外部請求進不來時，應先有一條從外到內的排查順序，而不是一開始就直接進 Pod 亂看。
4. debug 的核心不是背指令，而是先判斷自己正在驗證哪一層。
5. 今天的任務是先建立 debug 框架，不先把 describe、logs、exec 這些工具全部展開；工具語意留到回 VS Code 後再接。

## 建議教學順序

1. 先講 debug 為什麼需要先有排查框架，而不是先開工具箱。
2. 再講幾個常見 Pod 異常狀態各自代表什麼。
3. 接著把這些狀態和常見懷疑方向做最小對照。
4. 然後建立一條從外到內的 debug 順序，說清楚每一層在驗證什麼。
5. 最後用 2 到 3 個小問題做理解確認。
