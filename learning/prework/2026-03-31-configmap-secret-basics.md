### 今天一定要學會的最小骨架

1. ConfigMap 與 Secret 都能提供設定給 Pod，但兩者的分工重點在於資料是否敏感，以及是否適合直接放進版本控制流程。
2. Secret 的 `data` 與 `stringData` 不是兩種完全不同的資源，而是兩種提供內容的寫法；人手維護時，`stringData` 通常比較不容易因為手動 base64 而出錯。
3. `env`、`envFrom`、`valueFrom` 都和環境變數注入有關，但粒度不同：有的是逐個 key 指定，有的是整包匯入。
4. 不要把「跟資料庫有關」直接等於「一定是 Secret」；像 host、port、db name 這類值，要看它是否真的屬於敏感資訊。
5. 今天先建立概念骨架，不先深入 Secret 更新後 Pod 是否自動吃到新值，也不先展開 UTF-8 編碼踩坑。

### 建議教學順序

1. 先用白話講清楚 ConfigMap 與 Secret 各自在解什麼問題，以及為什麼 Kubernetes 要分成這兩種資源。
2. 再用幾個具體例子說明哪些設定通常放 ConfigMap，哪些通常放 Secret，並特別解釋為什麼 host / port 不一定算敏感資訊。
3. 接著講 Secret 的 `data` 與 `stringData` 差在哪裡，重點放在實務維護差異，而不是只背 API 定義。
4. 再講 `env`、`envFrom`、`valueFrom` 的差異，讓我知道什麼時候是逐個 key 指定，什麼時候是整批匯入。
